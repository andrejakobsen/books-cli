# Chapter subheaders for highlights

**Date:** 2026-07-25
**Status:** Design approved
**Scope:** `books/highlights.py` (shared renderer), `books/kobo_export.py` (passes label)

## Problem

Highlights render today as a flat list of `[!quote]+` callouts, each locator showing
`ch. 2 · 42%`. There is no way to scan a chapter's highlights as a group. Where a
source knows chapter titles (Kobo), we want to group highlights under a chapter
subheader so all highlights for a chapter collect visually under one heading.

A wrinkle: Kobo's chapter number is `VolumeIndex` — a **reading-order index**, not the
book's printed chapter number. It must not masquerade as a real chapter number in the
heading, but it is still useful to keep around (for search / disambiguation).

## Behavior

All logic lives in `render_highlights` in `books/highlights.py` so every source
shares one output format. The behavior is **gated on chapter data**, so page-based
sources (Highlighted) and chapter-less exports are unaffected.

### Trigger and fallback

- `render_highlights` scans the highlights. If **no** highlight has a non-empty
  `chapter_title`, it renders flat exactly as today (unchanged output).
- If at least one highlight has a `chapter_title`, it switches to **grouped mode**.

### Grouped output

Highlights are already sorted in reading order by each source. Walking them in order,
a new section header is emitted whenever the chapter changes (consecutive-run
grouping — reading-order sort keeps a chapter contiguous).

The chapter key for a run is:
- the `chapter_title` when present, else
- the `chapter_index` (index-only run), else
- none (a highlight with neither — rare leftover inside an otherwise-grouped book).

Header rendered per run:
- **Has title:** `## {chapter_title}`
- **Index only, no title:** `## Chapter {chapter_index}` (the approved edge-case
  fallback so no highlight is orphaned)
- **Neither:** no header — the callout(s) render bare, in place, preserving reading
  order.

Comment line, emitted directly under the header **only** when the run has both a title
and an index **and** the source supplied a label:

```
## {chapter_title}
%% {label} {chapter_index} %%
```

The label is a parameter passed by the source. Kobo passes `"Kobo ch."`, yielding
`%% Kobo ch. 12 %%`. The comment is invisible in Obsidian reading view but stays in
the source text and search. It is skipped for index-only headers (which already show
the number) and for sources that pass no label.

### Callout locator

Inside grouped mode the callout locator drops the now-redundant chapter component
(`ch. N` and the chapter-title fallback), keeping only `page`/`loc.` and progress
(`42%`). Links, tags, note body, and block anchors are unchanged.

In flat mode the locator is unchanged (`ch. 2 · 42%`).

### Example

```
## The Battle of Warsaw
%% Kobo ch. 12 %%

> [!quote]+ 42% · [[Trotsky]]
> quoted text here
^ch12-b3-5

> [!quote]+ 47%
> another highlight
^ch12-b8-2

## The Retreat
%% Kobo ch. 13 %%

> [!quote]+ 5%
> ...
^ch13-b1-0
```

## No `---` dividers

The renderer has never emitted `---` dividers between highlights (all versions join
blocks with a blank line). No code change is needed; a regression test locks this in
so grouped mode does not introduce them either. Existing vault notes generated by an
older version are refreshed (no dividers) on the next run.

## API

```python
render_highlights(highlights: list[Highlight], chapter_label: str | None = None) -> str
```

- `chapter_label=None` (default): grouping still happens when titles exist, but no
  `%% ... %%` comment line is emitted.
- Kobo calls `render_highlights(highlights, chapter_label="Kobo ch.")`.

Anchors (`build_anchors`) and the `Highlight` dataclass are unchanged.

## Testing

Unit tests in `tests/test_highlights.py`:

1. Flat fallback: no highlight has a chapter_title → output identical to today (no
   `##` headers).
2. Grouped: two chapters with titles → two `## Title` headers, each followed by
   `%% Kobo ch. N %%` when a label is passed; highlights land under the right header.
3. No label passed → headers present, comment lines absent.
4. Chapter-change boundary: consecutive highlights sharing a chapter share one header;
   a change emits a new header.
5. Locator drops `ch. N` in grouped mode (shows just `42%` / page).
6. Edge case: a highlight with `chapter_index` but empty title, alongside titled
   highlights → gets its own `## Chapter {index}` header, no comment line.
7. Regression: no `---` divider appears between highlights in either mode.
