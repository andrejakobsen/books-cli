# `books reset` — derived-store rebuild command

**Date:** 2026-07-30
**Status:** Approved design

## Problem

The CSV store has two kinds of files:

- **Self-healing** — `Data/Sources/<source>.csv` layers (`store.write_layer`
  rewrites each wholesale on re-import) and `Data/books.csv` (`store.merge` /
  `write_books_csv` rewrites it wholesale). These never go stale.
- **Accumulating** — `Data/Highlights/<book_id>.csv`. `store.write_highlights`
  only ever touches the file for the *current* `book_id`, so when a book's id
  changes, the old file is **orphaned forever**.

Changing the matching logic (e.g. the comma-date-subtitle fix that merges
"The Romanovs, 1613-1917" with "The Romanovs") reassigns `book_id`s, which
strands the previous highlight files. `merge` and `render` never clean them:
`render` simply ignores highlight files with no matching catalog book, so the
orphans persist silently.

There is no way to force a clean rebuild of the derived store from raw sources.

## Goal

Add a dedicated, destructive command that wipes the *purely-derived* store so a
subsequent `sync` (plus the manual `audible`/`covers` steps) rebuilds it from
raw sources — clearing orphaned highlight files.

## Non-goals

- Deleting notes (`Books/`/`Authors/`) — that is `render --refresh`'s job.
- Deleting source layers (`Data/Sources/*.csv`) or staged covers
  (`Data/Sources/_covers/`) — they self-replace on re-import, and wiping the
  `audible`/`covers` layers would discard network/transcription work that `sync`
  does not regenerate.
- Deleting raw imports (`Data/Imports/`).
- Any change to `render --refresh` or `sync --refresh` semantics.

## What `reset` deletes

| Path | Deleted? | Rationale |
|------|----------|-----------|
| `Data/books.csv` | ✅ | Fully regenerated by `merge`. |
| `Data/Highlights/` (whole dir) | ✅ | The only store that accumulates orphans. |
| `Data/Sources/*.csv` | ❌ | Self-replace on re-import; `audible`/`covers` not in `sync`. |
| `Data/Sources/_covers/` | ❌ | Staged images referenced by kept layers. |
| `Data/Imports/` | ❌ | Raw sources. |
| `Books/`, `Authors/` | ❌ | `render --refresh` owns note cleanup. |

## CLI

New module `books/commands/reset.py`, mirroring `books/commands/merge.py`, with a
`register(app)` that attaches `app.command("reset")`. Added to `CAPABILITIES` in
`books/cli.py`.

Options:

- `--output` / `-o` — vault override (standard `config.resolve_vault`).
- `--dry-run` — print the deletion plan (paths + highlight-file count); delete
  nothing.
- `--yes` / `-y` — skip the confirmation prompt.

Behavior:

1. Resolve vault. Compute the plan via `store.reset_store(vault, dry_run=True)`.
2. If nothing exists to delete → print an info message and exit 0 (no-op).
3. `--dry-run` → print the plan and exit 0.
4. Otherwise print the plan, then confirm:
   - `--yes` → proceed.
   - Interactive TTY → `ui.confirm("Delete the derived store?", default=False)`.
   - Non-interactive (stdin not a TTY) without `--yes` → `typer.BadParameter`
     (never silently nuke in scripts).
5. On confirm → `store.reset_store(vault)` and report counts via `ui.success`;
   on decline → `ui.info("Aborted.")` and exit 0.

## Store helper

Add to `books/core/store.py`:

```python
def reset_store(vault: Path, *, dry_run: bool = False) -> dict:
    """Delete the purely-derived store (books.csv + Highlights/).

    Returns {"books_csv": bool, "highlight_files": int} describing what was
    (or, under dry_run, would be) deleted. Keeps source layers and notes.
    """
```

- `books_csv`: whether `books_csv_path(vault)` exists (and, when not dry-run, is
  removed).
- `highlight_files`: count of `*.csv` under `highlights_dir(vault)` (and, when
  not dry-run, the whole directory is removed via `shutil.rmtree`).
- Idempotent: missing files/dirs yield zero/false and are not an error.

Filesystem logic lives in `store` (not the command) to match the
`command → store` layering and to keep it unit-testable without CLI plumbing.

## Testing (TDD)

`tests/core/test_store.py` — `reset_store`:
- deletes `books.csv` and the `Highlights/` dir on a real run;
- `dry_run=True` deletes nothing but returns the same counts;
- `highlight_files` counts every per-book CSV (including orphans);
- no-op when the store is absent (returns zeros/false, no error);
- leaves `Data/Sources/*.csv` and note folders untouched.

`tests/commands/test_reset.py` — CLI via Typer `CliRunner`:
- `--dry-run` prints the plan and deletes nothing;
- `--yes` deletes without prompting;
- non-TTY without `--yes` errors (`typer.BadParameter`);
- confirm-prompt "yes" deletes, "no" aborts and keeps files;
- no-op run reports cleanly and exits 0.

## Recovery flow this enables

```bash
books reset          # wipe derived store (books.csv + Highlights/)
books sync           # rebuild catalog + kobo/highlighted/readwise highlights + notes
books audible --all  # re-import audible highlights (cached) — not part of sync
books covers         # re-fetch any missing covers — not part of sync
books merge          # fold audible/covers layers in
books render         # materialize final notes
```
